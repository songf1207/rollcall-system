## 本轮修复结果

- 写操作统一通过数据库 write_locks 单行锁进入新事务；提交前刷新过期状态，保护点名、开课、计分、改判、转移和导入。增加真实并发与交错请求测试。
- TiDB 的实际并发验收发现，仅获取锁仍可能保留 RR 快照；已将连接显式设为 READ COMMITTED，并确认当前实例使用 pessimistic 事务。验收中发现的重复到场加分已追加冲正记录，未删除原始流水。隔离语义参考 [TiDB 官方文档](https://docs.pingcap.com/tidb/stable/transaction-isolation-levels/)。
- 所有 /api 接口要求 X-Teacher-Key；缺失/错误返回 401，未配置口令时拒绝业务请求。健康检查和接口文档保持可访问。
- 缺席拒绝问答输入；回答分数先校验原值，解决 0.46 四舍五入过关的问题。
- 校验专业 100 字符、班级 50 字符，超长行单独报错且好行可导入。
- 已结束场次、非当前轮次和功能禁用时不允许转移。
- 数据库不可用时健康检查返回 503，数据库异常统一返回可读错误。
- 部署蓝图补齐 TLS、教师口令及 CORS 输入，并使用经本机验证的版本约束；实际公网部署仍待仓库和托管账号准备好。
- 新增抽签复核 API，前端可展示原始权重、概率、随机键和复算状态。
- 云端检查还发现候选三列曾使用 FLOAT，导致约 1e-7 的复算误差；已升级为 DOUBLE 并保留历史记录。旧记录如果只能近似复算会返回 precision_limited，verified=null，不冒充精确验证通过。
